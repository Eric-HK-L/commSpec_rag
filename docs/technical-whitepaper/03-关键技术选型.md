# 03 — 关键技术选型

## 3.1 选型总览

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|----------|
| Web 框架 | FastAPI | 0.115 | 异步高性能、自动 OpenAPI 文档、类型安全 |
| 前端 | Next.js | 14 | SSR/SSG 混合渲染、App Router、React 生态 |
| 向量数据库 | Milvus | 2.4 | GPU 加速索引、标量过滤、混合检索支持 |
| 嵌入模型 | BGE-M3 | - | 多语言 (100+)、1024-dim、Dense+Sparse 双向量 |
| LLM 接口 | OpenAI 兼容 | - | 兼容 vLLM/LocalAI/ollama 等私有部署 |
| 文档提取 | Pandoc | - | 通用文档转换、表格/公式/标题结构保留 |
| 精排模型 | BGE-Reranker-v2-M3 | - | Cross-Encoder 高精度重排序 |
| 监控 | Prometheus | client 0.21 | 标准时序指标、Grafana 可视化 |
| 配置 | pydantic-settings | 2.7 | 类型校验、.env 自动加载 |

## 3.2 LLM 选型对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| OpenAI GPT-4o-mini | 质量最高、生态完善 | 需外网、按量付费 | 开发/评测 |
| vLLM + Qwen2.5 | 私有部署、免费 | 需 GPU (≥24GB) | 生产环境 |
| ollama + Llama3 | 轻量、本地运行 | 能力弱于 GPT-4 | 离线环境 |
| LocalAI | Docker 一键部署 | 社区维护 | 容器化部署 |

**当前默认**: OpenAI GPT-4o-mini (通过 `LLM_BASE_URL` 可切换到任意兼容端点)

## 3.3 向量数据库对比

| 方案 | 优势 | 劣势 | 选择 |
|------|------|------|------|
| Milvus | GPU 索引、混合检索、生产级 | 需独立部署 | ✅ |
| Chroma | 轻量、Python 原生 | 规模受限、无 BM25 | ❌ |
| Qdrant | Rust 高性能 | 社区较新 | ❌ |
| FAISS | Meta 开源、纯本地 | 无持久化、无过滤 | ❌ |
| Elasticsearch | 全文检索成熟 | 向量能力弱、重 | ❌ |

Milvus 选型核心决策:
- **标量过滤**: `spec_number == "38.413" && release == "R18"` 原生支持
- **分区键**: 按 release 分区，增量摄入时只重建目标分区索引
- **混合检索**: Dense ANN + BM25 两种检索路径，通过 RRF 融合

## 3.4 嵌入模型对比

| 模型 | 维度 | 语言 | 特点 | 选择 |
|------|------|------|------|------|
| BGE-M3 | 1024 | 100+ | 多语言、Dense+Sparse 双输出 | ✅ |
| text-embedding-3-small | 1536 | 多语言 | OpenAI API、需外网 | 备选 |
| all-MiniLM-L6-v2 | 384 | EN only | 轻量、快速 | ❌ |
| E5-mistral-7b | 4096 | EN only | 需 GPU、过大 | ❌ |

**BGE-M3 选型理由**:
1. 同时输出 Dense 向量 (ANN 检索) + 稀疏词汇权重 (BM25 替代)
2. 1024 维度在精度和存储间取得平衡
3. 原生支持中文，适配国内电信客户需求
4. MPS 后端可在 Apple Silicon 上运行

## 3.5 缓存策略分层

参见 [[08-性能优化策略]] 获取详细缓存设计。

```
请求层: TTLCache (内存 256 条, TTL 1h)
  → 相同查询 1 小时内直接返回缓存结果

嵌入层: EmbeddingCache (SQLite)
  → SHA256 索引, 避免重复计算 chunk 嵌入
  → 批量查询: SELECT ... WHERE hash IN (...)
  → O(log n) vs 散文件 O(n)

文件层: .npy 文件缓存
  → 向后兼容, EmbeddingCache 兜底
```

## 3.6 前端技术决策

| 需求 | 方案 | 理由 |
|------|------|------|
| 框架 | Next.js 14 (App Router) | SSR + 静态导出, SEO 友好 |
| 样式 | Tailwind CSS | 原子化 CSS, 快速开发 |
| Markdown | react-markdown + remark-gfm | 表格/GitHub 风格渲染 |
| 状态管理 | React useState + useRef | 轻量, 无需 Redux |
| 流式 | SSE (Server-Sent Events) | 原生浏览器支持, 逐 token 推送 |
| 主题 | CSS 变量 + next-themes | 暗色/亮色切换 |
| 构建 | Turbopack (dev) | 比 Webpack 快 10x |

## 3.7 文档处理管线

DOCX → Markdown → Chunk → Embed → Insert 全流程:

```
[3GPP FTP]
    │
    ▼
Pandoc Extractor
  · 表格 → Markdown table
  · 标题层级 → ### Heading
  · 公式 → LaTeX
    │
    ▼
HeaderAware Splitter
  · 按 ### 边界分块
  · 父标题追踪
  · Section ID 继承
  · 55KB 字节硬上限
    │
    ▼
Batch Embedder
  · BGE-M3 1024-dim
  · SQLite 缓存优先
  · 文件缓存兜底
  · MPS 加速 (Apple Silicon)
    │
    ▼
Milvus Store
  · Collection: TeleComm_specs
  · Fields: id, text, embedding (1024), spec_number, release, series, ...
  · Index: IVF_FLAT (nlist=1024)
  · Partition Key: release
```
