# 07 — 文档摄入管线

## 7.1 管线总览

文档摄入将 3GPP DOCX 规范转换为可检索的向量化 chunks，支持全量和增量两种模式。

```
scripts/bulk_ingest.py  ← CLI 入口
    │
    ├── --full-rebuild   → 全量重建模式
    └── (默认)            → 增量模式
         │
         ├── Step 1: 查找 DOCX → find_docx_files()
         ├── Step 2: 提取 → DoclingExtractor
         ├── Step 3: 分块 → HeaderAwareSplitter
         ├── Step 4: 清单管理 → IngestionManifest
         ├── Step 5: 嵌入 → BatchEmbedder (BGE-M3)
         │                  或 MPSChunkedEmbedder (Apple Silicon)
         ├── Step 6: 入库 → MilvusStore.insert()
         └── Step 7: BM25 → build_bm25() / rebuild_bm25_from_collection()
```

## 7.2 文档发现 (`find_docx_files()`)

```
data/documents/{Release}/
  ├── 21_series/  (UMTS)
  ├── 22_series/  (Service aspects)
  ├── 23_series/  (5G Core)
  ├── 24_series/  (Signalling)
  ├── 36_series/  (LTE)
  └── 38_series/  (NR Radio)
```

- 递归扫描 `*.docx`
- 跳过 `_cover.docx` (仅封面页)
- 按 `parent_name` (series) → `name` 排序
- 从文件名解析: `TS_38.300_R18_v17.0.0.docx` → spec=38.300, release=R18

## 7.3 DOCX 提取 (Docling)

```python
extractor = DoclingExtractor()
result = extractor.extract_file(docx_path)
# → ExtractionResult(
#     source_file="TS_38.413_R18.docx",
#     markdown="# 8.3 PDU Session...\n...",
#     spec_number="38.413",
#     release="R18"
#   )
```

Docling 能力:
- 表格 → Markdown table (对齐、合并单元格)
- 标题层级 → H1-H6 (#, ##, ###...)
- 公式 → LaTeX 标记
- 页眉/页脚 → 自动过滤
- 自动检测 Release (从文档内容头提取)

## 7.4 语义分块 (HeaderAwareSplitter)

```python
splitter = HeaderAwareSplitter(
    max_chunk_chars=2500,
    chunk_overlap_chars=100,
)
chunks = splitter.split_document(markdown, doc_meta)
```

### 分块策略
1. 按 `###` 三级标题边界切分（保持语义完整性）
2. 每个 chunk 继承父标题 (parent_title)、章节号 (parent_section_id)
3. 超大 chunk (>55KB UTF-8 bytes) 在段落边界精细拆分
4. 字节硬截断兜底 (极少数合并单元格残留)

### Chunk 元数据
```python
@dataclass
class Chunk:
    text: str                 # 纯文本内容
    doc_id: str               # 文档标识 (如 "TS_38.413_R18")
    series: int               # 系列号 (如 38)
    spec_number: str           # 规范号 (如 "38.413")
    release: str              # Release (如 "R18")
    parent_section_id: str    # 章节号 (如 "8.3.1")
    parent_title: str          # 父标题 (如 "PDU Session Resource Setup")
    chunk_index: int           # 文档内序号
    embedding: np.ndarray     # 嵌入向量 (后填充)
```

## 7.5 清单管理 (`manifest.py`)

```python
manifest = IngestionManifest()
manifest.load()  # 从 ingestion_state.json 加载

# 版本比较
existing = manifest.find(spec_number="38.413", release="R18")
if existing and compare_versions("i80", existing.latest_version) > 0:
    # 新版本 → 替换
    store.delete_by_filter(f'spec_number=="38.413" && release=="R18"')
    manifest.mark(spec_number, release, version, file_path, sha256, chunk_count)

manifest.save()
```

### Manifest 结构 (`ingestion_state.json`)
```json
{
  "specs": {
    "38.413|R18": {
      "spec_number": "38.413",
      "release": "R18",
      "latest_version": "i80",
      "file_path": "data/documents/R18/38_series/TS_38.413_R18_v17.8.0.docx",
      "sha256": "abc123...",
      "chunk_count": 245,
      "ingested_at": "2026-07-15T10:30:00Z"
    }
  }
}
```

### 增量逻辑
1. 扫描文件系统 → 计算 SHA256
2. 对比 manifest 已有记录
3. 新增 (无记录) → 摄入
4. 版本升级 (新版 > 旧版) → 替换 (delete old + insert new)
5. 内容相同 → 跳过
6. 孤儿 (文件删除) → 清理 manifest + 删除向量

## 7.6 批量嵌入 (`embedder.py`)

### 双层缓存策略
```
BatchEmbedder.embed_batch(texts)
    │
    ├── _check_cache(texts)
    │     ├── Layer 1: EmbeddingCache (SQLite)
    │     │     get_batch(texts) → {hash: embedding}
    │     └── Layer 2: File Cache (.npy)
    │          逐文件读取 → 回填 SQLite
    │
    └── _embed_with_fallback(uncached_texts)
          ├── API 优先: self._client.embed(texts)  # OpenAI-compatible
          └── 本地降级: BGE-M3 via SentenceTransformers
```

### 缓存命中流程
1. 批量查询 SQLite: `SELECT hash, embedding FROM embeddings WHERE hash IN (...)`
2. SQLite 未命中 → 检查文件缓存 `.npy`
3. 文件缓存命中 → 回填 SQLite (渐进式迁移)
4. 全部未命中 → 调用嵌入模型 → 双写 (SQLite + File)

### MPS 加速 (Apple Silicon)
```python
if MPSChunkedEmbedder.is_mps_available():
    # 独立子进程: 避免 gRPC 状态污染 + Metal 多进程死锁
    embeddings = _embed_via_subprocess(texts)
    # 单 worker: Apple MPS 不支持多进程 GPU
    # 超时动态计算: 保守 1 t/s + 1800s 模型加载
```

### 硬编码常量
| 参数 | 值 | 说明 |
|------|-----|------|
| batch_size | 32 | API 模式批次大小 |
| segment_size | 5000 | MPS 分段大小 |
| timeout | max(600, N/1+1800) | 动态超时秒数 |
| MAX_CHUNK_BYTES | 55000 | 入库前安全检查 |

## 7.7 版本管理

### 大版本共存
```
key = f"{spec_number}|{release}"
# 38.413|R18 与 38.413|R19 各自独立
```

### 小版本替换
```
compare_versions("i80", "i70") > 0  → 替换
compare_versions("i80", "i80") == 0 → 同版本比较 SHA256
```

### 版本解析
```
TS_38.413_R18_v17.8.0.docx   → "i80"  (版本号 i80)
38300-rel18.docx              → ""     (无版本)
23700-18-i00.docx             → "i00"  (子规范号版本)
38101-2-i40.docx              → "i40"  (子部分)
```

## 7.8 容错与恢复

1. **Checkpoint**: 提取阶段完成后保存 `chunks_checkpoint.pkl`，嵌入失败后可从 checkpoint 恢复
2. **断点续传**: `--resume-from-checkpoint` 跳过提取，直接从嵌入+入库开始
3. **Milvus 断点**: 检测已有向量数，自动跳过已入库段
4. **段内隔离**: 每 5000 条一段，段失败不影响已入库段
5. **文件异常**: 单个 DOCX 处理失败 → 跳过继续 (不阻塞整体)
