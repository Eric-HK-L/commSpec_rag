## 9.2 Docker 部署

### `docker-compose.yml` (项目根目录)
```yaml
services:
  api:
    build:
      context: .
      dockerfile: deploy/Dockerfile
    ports:
      - "8000:8000"
    environment:
      - MILVUS_HOST=milvus
      - LLM_BASE_URL=${LLM_BASE_URL}
      - LLM_API_KEY=${LLM_API_KEY}
    volumes:
      - ./data:/app/data
      - ./logs:/app/logs
    depends_on:
      - milvus

  frontend:
    build:
      context: .
      dockerfile: deploy/Dockerfile.frontend
    ports:
      - "3000:3000"
    environment:
      - NEXT_PUBLIC_API_URL=http://api:8000

  milvus:
    image: milvusdb/milvus:v2.4.10
    ports:
      - "19530:19530"
      - "9091:9091"
    volumes:
      - milvus_data:/var/lib/milvus

  grafana:  # 可选
    image: grafana/grafana
    ports:
      - "3001:3000"
    volumes:
      - ./deploy/grafana-dashboard.json:/etc/grafana/provisioning/dashboards/rag.json
```

### 启动脚本 (`deploy/start.sh`)
```bash
#!/bin/bash
docker-compose up -d milvus          # Step 1: 启动向量库
sleep 10                              # 等待 Milvus 就绪
docker-compose up -d api              # Step 2: 启动 API
docker-compose up -d frontend         # Step 3: 启动前端
# 首次部署需运行摄入:
# docker-compose exec api python scripts/bulk_ingest.py
```

## 9.4 部署流程

### 首次部署
```bash
# 1. 克隆仓库
git clone <repo-url> && cd 3GPP_RAG_project

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env: 填写 LLM_API_KEY

# 3. 放置文档
# 将 DOCX 文件放入 data/documents/R18/ 对应系列目录

# 4. 安装 Python 依赖
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 5. 启动 Milvus
docker-compose up -d milvus

# 6. 运行摄入 (首次约 30-60 分钟)
python scripts/bulk_ingest.py

# 7. 启动服务
python -m src.main

# 8. (可选) 启动前端
cd frontend && npm install && npm run dev
```

### 增量更新
```bash
# 放置新 DOCX 文件后
python scripts/bulk_ingest.py  # 自动检测增量
# 或通过 Admin API
curl -X POST http://localhost:8000/api/v1/admin/ingest/trigger
```

## 9.5 CI/CD

### GitHub Actions (`.github/workflows/ci.yml`)
```yaml
on:
  push:
    branches: [main, master]
    paths:
      - "src/**"
      - "tests/**"
      - "scripts/**"
      - "requirements.txt"

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.11", "3.12"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
      - run: pip install -r requirements.txt pytest
      - run: pytest tests/ -v --tb=short
      - run: python -m tests.eval.run_eval --dry-run

  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: cd frontend && npm ci && npm run build
```

环境限制:
- **无 Milvus**: 跳过集成测试，仅运行不依赖 Milvus 的单元测试
- **无 GPU**: 嵌入测试使用小样本 mock

## 9.6 监控 (`monitoring.py`)

### Prometheus 指标
| 指标名 | 类型 | 标签 | 说明 |
|--------|------|------|------|
| `rag_requests_total` | Counter | route, status | HTTP 请求总数 |
| `rag_request_duration_seconds` | Histogram | route | 请求延迟分布 |
| `rag_search_duration_seconds` | Histogram | - | 检索耗时 |
| `rag_llm_calls_total` | Counter | - | LLM 调用次数 |
| `rag_llm_tokens_total` | Counter | type (prompt/completion) | Token 消耗 |
| `rag_llm_duration_seconds` | Histogram | - | LLM 耗时 |
| `rag_errors_total` | Counter | type | 错误计数 |
| `rag_multi_hop_total` | Counter | - | 多跳触发次数 |

### 访问端点
```
GET /metrics   → Prometheus 格式指标
GET /health    → {"status": "ok", "milvus": true}
```

## 9.7 日志管理

### 日志配置
```python
# src/main.py
logging.basicConfig(
    level=getattr(logging, settings.log_level),
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    handlers=[
        logging.StreamHandler(sys.stdout),     # 控制台输出
        logging.FileHandler(settings.log_abs_file),  # 文件持久化
    ],
)
```

### 日志文件
| 文件 | 用途 |
|------|------|
| `logs/app.log` | 应用主日志 (API 请求、LLM 调用、错误) |
| `logs/bulk_ingest_v3.log` | 摄入日志 (通过 Admin API 触发) |
| `logs/bulk_ingest_v4.log` | 摄入日志 (新版) |

### 日志级别建议
- **开发**: `DEBUG` — 输出全部调试信息
- **生产**: `INFO` — 仅关键事件和错误
- **排查**: `DEBUG` — 临时启用详细日志

## 9.9 故障排查

| 症状 | 可能原因 | 排查步骤 |
|------|----------|----------|
| `Milvus 连接失败` | Milvus 未启动 | `docker ps \| grep milvus` |
| `嵌入模型下载慢` | HuggingFace 被墙 | 设置 HF_ENDPOINT=https://hf-mirror.com |
| `摄入内存溢出` | MPS 内存泄漏 | 设置 EMBEDDING_DEVICE=cpu |
| `LLM 超时` | API 不可达 | 检查 LLM_BASE_URL, 确认网络通 |
| `前端 404` | 路由配置错误 | 检查 next.config.ts 的 rewrites |
| `测试失败` | 依赖缺失 | `pip install -r requirements.txt` |

## 9.10 安全建议

1. **API Key**: `.env` 中的 LLM_API_KEY 不要提交到 Git
2. **CORS**: 生产环境将 `allow_origins` 限制为具体域名
3. **认证**: 启用 `APIKeyMiddleware` (当前支持，默认宽松)
4. **HTTPS**: 生产环境使用 Nginx 反向代理 + Let's Encrypt
5. **防火墙**: 限制 Milvus 端口 (19530) 仅本地访问

## 9.11 Nginx 反向代理配置（生产推荐）

```nginx
# /etc/nginx/sites-available/3gpp-rag
server {
    listen 443 ssl http2;
    server_name rag.your-company.com;

    ssl_certificate     /etc/letsencrypt/live/rag.your-company.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/rag.your-company.com/privkey.pem;

    # 前端
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # API
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 120s;  # LLM 调用可能较慢
        proxy_buffering off;       # SSE 流式需要
    }

    # API 其他端点
    location ~ ^/(health|metrics|mcp) {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
    }

    # 限制访问 Admin 路径到内网
    location /admin {
        allow 10.0.0.0/8;
        allow 172.16.0.0/12;
        allow 192.168.0.0/16;
        deny all;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }
}
```

## 9.12 systemd 服务配置（Linux 生产环境）

```ini
# /etc/systemd/system/3gpp-rag-api.service
[Unit]
Description=3GPP RAG API Server
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=rag
WorkingDirectory=/opt/3gpp_rag
ExecStart=/usr/bin/docker compose -f deploy/docker-compose.yml up api
ExecStop=/usr/bin/docker compose -f deploy/docker-compose.yml stop api
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
# 启用服务
sudo systemctl daemon-reload
sudo systemctl enable 3gpp-rag-api
sudo systemctl start 3gpp-rag-api
sudo systemctl status 3gpp-rag-api
```

## 9.14 离线环境部署

> 适用于无法访问互联网的内网/隔离环境。

### 步骤

```bash
# 1. 在有网络的机器上准备离线包
pip download -r requirements.txt -d ./offline_packages/
# 将 offline_packages/ 拷贝到离线服务器

# 2. 在有网络的机器上下载 Docker 镜像
docker pull milvusdb/milvus:v2.4.10
docker save milvusdb/milvus:v2.4.10 -o milvus_v2.4.10.tar
# 将 tar 文件拷贝到离线服务器

# 3. 在离线服务器上安装
pip install --no-index --find-links=./offline_packages/ -r requirements.txt
docker load -i milvus_v2.4.10.tar

# 4. 预下载 BGE-M3 模型（在有网络的机器上）
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-m3')"
# 模型缓存位置: ~/.cache/huggingface/hub/
# 将 models--BAAI--bge-m3 目录拷贝到离线服务器的相同位置

# 5. 正常启动
cp .env.example .env
# 编辑 .env: LLM_BASE_URL 指向内网 LLM 服务
python -m src.main
```

参见 `scripts/install_offline.sh` 和 `scripts/prepare_offline.py` 获取自动化脚本。
