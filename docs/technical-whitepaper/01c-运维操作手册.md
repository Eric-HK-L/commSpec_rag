# 01c — 运维操作手册

> **目标读者**: 系统运维人员、负责日常维护的非开发人员。
> **目标**: 掌握日常检查、备份恢复、版本升级、应急处理等运维操作。

## 1. 日常巡检清单

### 1.1 每日检查（5 分钟）

| # | 检查项 | 操作 | 正常标准 |
|---|--------|------|----------|
| 1 | 服务运行状态 | `docker ps` 查看 milvus/api/frontend 容器 | 三个容器均为 `Up` 状态 |
| 2 | API 健康检查 | `curl http://localhost:8000/health` | `milvus: true` |
| 3 | 前端访问 | 浏览器打开 `http://localhost:3000` | 正常显示聊天界面 |
| 4 | 错误日志扫描 | `grep ERROR logs/app.log \| tail -20` | 无新增 ERROR（偶发 LLM 超时可接受） |
| 5 | 磁盘空间 | `df -h /` | 可用空间 > 10GB |

### 1.2 每周检查（15 分钟）

| # | 检查项 | 操作 | 正常标准 |
|---|--------|------|----------|
| 1 | 嵌入缓存大小 | `curl localhost:8000/api/v1/admin/system` | `embedding_cache_mb` 在合理范围 |
| 2 | 日志文件大小 | `ls -lh logs/` | `app.log` < 500MB（建议配置日志轮转） |
| 3 | BM25 索引状态 | Admin 面板 → 仪表盘 | BM25 状态正常 |
| 4 | Milvus 集合大小 | `curl localhost:8000/api/v1/admin/stats` | `total_chunks` 与预期匹配 |
| 5 | 摄入清单一致性 | Admin 面板 → 文档管理 | 文档数与 `data/documents/` 中一致 |

### 1.3 每月检查（30 分钟）

| # | 检查项 | 操作 |
|---|--------|------|
| 1 | 完整备份 | 参见 §3 备份与恢复 |
| 2 | Release 监控报告 | 查看 `logs/app.log` 中 `📢 Release 变更检测` 日志 |
| 3 | 性能基准测试 | `python -m pytest tests/benchmark/ -v` 对比历史数据 |
| 4 | 依赖更新检查 | `pip list --outdated` 检查 Python 包更新 |
| 5 | 磁盘清理 | 清理过期日志、旧 checkpoint 文件 |

## 2. 常用运维操作

### 2.1 启动/停止/重启服务

```bash
# === Docker 方式 ===
cd /path/to/3GPP_RAG_project

# 启动所有服务
docker compose -f deploy/docker-compose.yml up -d

# 停止所有服务
docker compose -f deploy/docker-compose.yml stop

# 重启所有服务
docker compose -f deploy/docker-compose.yml restart

# 仅重启 API（配置变更后）
docker compose -f deploy/docker-compose.yml restart api

# 仅重启前端（前端代码更新后）
docker compose -f deploy/docker-compose.yml restart frontend

# 查看服务日志
docker compose -f deploy/docker-compose.yml logs -f --tail=100 api
docker compose -f deploy/docker-compose.yml logs -f --tail=100 milvus

# === 本地开发方式 ===
# 启动: python -m src.main
# 停止: Ctrl+C
# 前端: cd frontend && npm run dev
```

### 2.2 查看运行状态

```bash
# API 健康检查
curl http://localhost:8000/health
# → {"status":"ok","milvus":true,"uptime_seconds":123456}

# 完整系统信息（含缓存、在线搜索状态）
curl http://localhost:8000/api/v1/admin/system | python -m json.tool
# → Python版本、内存、磁盘、Milvus连接、缓存条目等

# 系统统计
curl http://localhost:8000/api/v1/admin/stats | python -m json.tool
# → total_chunks、total_documents、嵌入缓存命中率等
```

### 2.3 查看日志

```bash
# 实时查看应用日志（最后 50 行）
tail -f logs/app.log

# 查看最近 100 行错误
grep -i "error\|exception\|traceback" logs/app.log | tail -100

# 查看最近 LLM 调用记录
grep "LLM" logs/app.log | tail -20

# 查看摄入日志
tail -100 logs/bulk_ingest_v4.log

# 通过 API 查看日志
curl "http://localhost:8000/api/v1/admin/logs?level=ERROR&lines=50"
```

### 2.4 更新文档库（增量摄入）

```bash
# 1. 将新 DOCX 文件放入 data/documents/R18/ 对应系列目录
# 2. 执行增量摄入（自动检测新增/更新的文档）
python scripts/bulk_ingest.py

# 或通过 API 触发（不阻塞终端）
curl -X POST "http://localhost:8000/api/v1/admin/ingest/trigger?mode=incremental"

# 3. 查看摄入进度
curl http://localhost:8000/api/v1/admin/ingest/status

# 4. 摄入完成后验证
curl http://localhost:8000/api/v1/admin/stats | python -m json.tool
```

### 2.5 全量重建向量库

> ⚠️ **警告**: 此操作会清空现有向量数据并重新摄入，执行期间搜索不可用。

```bash
# 全量重建
python scripts/bulk_ingest.py --full-rebuild

# 流程：
# 1. 删除 Milvus collection
# 2. 重新提取所有 DOCX → Markdown
# 3. 重新分块 + 嵌入 + 入库
# 4. 重建 BM25 索引
# 预计耗时：与文档数量成正比（400 份约 1-2 小时）
```

## 3. 备份与恢复

### 3.1 需要备份的数据

| 数据 | 位置 | 大小估算 | 备份频率 |
|------|------|----------|----------|
| Milvus 向量数据 | Docker Volume `milvus_data` | 2-5 GB | 每周 |
| BM25 索引 | `data/vectors/bm25_index.pkl` | ~2 GB | 每周 |
| 嵌入缓存 | `data/embedding_cache.db` | ~200 MB | 每周 |
| 摄入清单 | `data/manifest/ingestion_state.json` | ~50 KB | 每次摄入后 |
| 环境配置 | `.env` | ~1 KB | 每次修改后 |
| 应用日志 | `logs/` | ~100 MB | 每月 |
| 原始 DOCX | `data/documents/` | ~500 MB | 每次下载后 |
| 用户反馈 | `data/cache/feedback.jsonl` | ~1 MB | 每周 |

### 3.2 备份操作

```bash
# === 方案 A: 快速备份（推荐） ===
BACKUP_DIR="/backup/commSpec_rag/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$BACKUP_DIR"

# 1. 备份配置文件
cp .env "$BACKUP_DIR/"
cp .env.example "$BACKUP_DIR/"

# 2. 备份数据文件
cp -r data/manifest "$BACKUP_DIR/"
cp data/vectors/bm25_index.pkl "$BACKUP_DIR/"
cp data/embedding_cache.db "$BACKUP_DIR/"
cp data/cache/feedback.jsonl "$BACKUP_DIR/" 2>/dev/null || true

# 3. 备份 Milvus（Docker Volume）
docker run --rm \
  -v commSpec_rag_milvus_data:/data:ro \
  -v "$BACKUP_DIR/milvus":/backup \
  alpine tar czf /backup/milvus_data.tar.gz -C /data .

# 4. 备份原始文档
tar czf "$BACKUP_DIR/documents.tar.gz" -C data documents/R18/

echo "✅ 备份完成: $BACKUP_DIR"
ls -lh "$BACKUP_DIR"

# === 方案 B: 完整备份（含向量数据导出） ===
# 通过 Milvus 命令行工具导出（需要安装 milvus-cli）
# pip install milvus-cli
# milvus-cli export -c TeleComm_specs -o "$BACKUP_DIR/milvus_export.json"
```

### 3.3 恢复操作

```bash
# === 场景 1: 配置文件丢失 ===
cp /backup/commSpec_rag/20260715_120000/.env .env

# === 场景 2: 嵌入缓存损坏 ===
# 症状: 摄入时大量 "缓存读取失败" 错误
# 方案: 删除缓存文件，重新摄入（嵌入会自动重建）
rm data/embedding_cache.db
python scripts/bulk_ingest.py

# === 场景 3: BM25 索引损坏 ===
# 症状: 搜索返回无 BM25 结果
# 方案: 从 Milvus 重建 BM25
python -c "
from src.retriever.bm25_index import rebuild_bm25_from_collection
rebuild_bm25_from_collection()
"

# === 场景 4: Milvus 数据损坏 ===
# 症状: Milvus 无法启动 / 查询报错
# 方案: 重新摄入（从原始 DOCX）
docker compose -f deploy/docker-compose.yml down -v milvus  # 删除 Volume
docker compose -f deploy/docker-compose.yml up -d milvus
sleep 30
python scripts/bulk_ingest.py --full-rebuild

# === 场景 5: 完整恢复（全部从备份） ===
BACKUP_DIR="/backup/commSpec_rag/20260715_120000"
cp "$BACKUP_DIR/.env" .
cp "$BACKUP_DIR/bm25_index.pkl" data/vectors/
cp "$BACKUP_DIR/embedding_cache.db" data/
cp -r "$BACKUP_DIR/manifest" data/
# Milvus Volume 恢复：
docker compose -f deploy/docker-compose.yml down
docker run --rm \
  -v commSpec_rag_milvus_data:/data \
  -v "$BACKUP_DIR/milvus":/backup \
  alpine tar xzf /backup/milvus_data.tar.gz -C /data
docker compose -f deploy/docker-compose.yml up -d
```

## 4. 版本升级指南

### 4.1 升级前检查

```bash
# 1. 确认当前版本（查看 Git tag 或 CHANGELOG）
git describe --tags

# 2. 备份数据（必须！）
# 按 §3.2 执行完整备份

# 3. 记录当前配置
cp .env .env.backup.$(date +%Y%m%d)

# 4. 检查服务状态
curl http://localhost:8000/health
docker ps
```

### 4.2 小版本升级 (v0.2.0 → v0.2.1)

```bash
# 1. 停止服务
docker compose -f deploy/docker-compose.yml stop api frontend

# 2. 拉取最新代码
git pull origin main

# 3. 检查配置变更
diff .env .env.example
# 如有新增配置项，手动添加到 .env

# 4. 更新依赖
source .venv/bin/activate
pip install -r requirements.txt
cd frontend && npm install && cd ..

# 5. 重建 Docker 镜像
docker compose -f deploy/docker-compose.yml build api frontend

# 6. 启动服务
docker compose -f deploy/docker-compose.yml up -d

# 7. 验证
curl http://localhost:8000/health
```

### 4.3 大版本升级 (v0.2.x → v0.3.x)

```bash
# 大版本可能涉及：
# - 向量库 schema 变更 → 需要全量重建
# - 配置文件结构变更 → 需要迁移 .env
# - 嵌入模型切换 → 需要重新嵌入

# 1. 完整备份（必须！）
# 按 §3.2 执行

# 2. 阅读 Release Notes（了解破坏性变更）

# 3. 停止全部服务
docker compose -f deploy/docker-compose.yml down

# 4. 拉取新版本
git fetch --tags
git checkout v0.3.0

# 5. 迁移配置（对照 .env.example）
vimdiff .env .env.example

# 6. 清空旧数据（如果是 schema 变更）
docker compose -f deploy/docker-compose.yml down -v milvus

# 7. 重新部署
docker compose -f deploy/docker-compose.yml up -d milvus
sleep 30
python scripts/bulk_ingest.py --full-rebuild

# 8. 验证
curl http://localhost:8000/api/v1/admin/stats
```

## 5. 性能监控

### 5.1 关键指标阈值

| 指标 | 正常范围 | 警告阈值 | 严重阈值 | 排查方向 |
|------|----------|----------|----------|----------|
| API P50 延迟 | < 500ms | > 1s | > 3s | LLM 调用慢 / 网络问题 |
| 检索 P50 延迟 | < 200ms | > 500ms | > 1s | Milvus 索引重建 / 磁盘慢 |
| 错误率 | < 1% | > 5% | > 10% | 检查 logs/app.log ERROR |
| Milvus 内存 | < 4GB | > 6GB | > 8GB | 考虑扩展服务器 |
| 磁盘使用率 | < 70% | > 80% | > 90% | 清理日志 / 扩展磁盘 |
| 嵌入缓存命中率 | > 60% | < 40% | < 20% | 缓存文件可能损坏 |

### 5.2 Prometheus + Grafana 监控

```bash
# Prometheus 端点
curl http://localhost:8000/metrics

# 关键指标：
# rag_requests_total{route="/api/v1/ask",status="200"}  → 成功问答数
# rag_request_duration_seconds_bucket{le="1.0"}          → 1 秒内完成的比例
# rag_search_duration_seconds_sum                         → 检索总耗时
# rag_llm_calls_total                                     → LLM 调用总数
# rag_errors_total{type="llm_timeout"}                   → LLM 超时次数
```

### 5.3 性能调优速查

| 问题 | 调整项 | 位置 |
|------|--------|------|
| 搜索太慢 | 减少 `DENSE_TOP_K` 从 100→50 | `.env` |
| 问答太慢 | 减少 `LLM_MAX_TOKENS` 从 2048→1024 | `.env` |
| 嵌入太慢 (GPU) | 设置 `EMBEDDING_DEVICE=cuda` | `.env` |
| 嵌入太慢 (Mac) | 设置 `EMBEDDING_DEVICE=mps`，注意 MPS 内存 | `.env` |
| 缓存命中率低 | 检查 `data/embedding_cache.db` 是否存在/可读 | 文件系统 |
| Milvus 内存大 | 调整 Docker 内存限制 | `docker-compose.yml` |
| LLM 调用多 | 增大 `TTLCache maxsize` (当前 256→512) | `src/generator/pipeline.py` |

## 6. 安全运维

### 6.1 安全基线

```bash
# 1. 确保 .env 权限
chmod 600 .env

# 2. 确保 API Key 未提交到 Git
grep -r "LLM_API_KEY" .git/ 2>/dev/null || echo "✅ API Key 未泄露"

# 3. 限制 Milvus 端口仅本地访问
# 在 docker-compose.yml 中 milvus ports 改为:
#   - "127.0.0.1:19530:19530"

# 4. 定期更新依赖
pip list --outdated
npm outdated --cwd frontend/

# 5. 检查日志中无敏感信息
grep -i "api.key\|password\|secret" logs/app.log
```

### 6.2 防火墙规则

| 端口 | 服务 | 建议访问范围 |
|------|------|-------------|
| 8000 | API (FastAPI) | 内网 / 仅前端服务器 |
| 3000 | 前端 (Next.js) | 用户网络 |
| 19530 | Milvus gRPC | 仅 localhost |
| 9091 | Milvus 健康检查 | 仅 localhost |

## 7. 应急处理流程

### 7.1 服务不可用

```bash
# 1. 快速诊断
curl http://localhost:8000/health       # API 是否活着？
docker ps | grep milvus                 # Milvus 是否运行？
docker ps | grep api                    # API 容器是否运行？

# 2. 常见恢复操作（优先级从高到低）
# a) 重启 API
docker compose -f deploy/docker-compose.yml restart api

# b) 重启全部服务
docker compose -f deploy/docker-compose.yml restart

# c) 重建并重启
docker compose -f deploy/docker-compose.yml up -d --force-recreate

# d) 全量重建（最后手段 — 数据不丢，但耗时）
docker compose -f deploy/docker-compose.yml down
docker compose -f deploy/docker-compose.yml up -d milvus
sleep 30
python scripts/bulk_ingest.py --full-rebuild
docker compose -f deploy/docker-compose.yml up -d
```

### 7.2 磁盘空间不足

```bash
# 1. 诊断
df -h /
du -sh logs/ data/cache/ data/vectors/ .venv/

# 2. 清理（按安全性排序）
# 安全清理：
find logs/ -name "*.log" -mtime +30 -delete   # 删除 30 天前的日志
rm data/chunks_checkpoint.pkl                  # 删除旧 checkpoint

# 谨慎清理：
rm data/embedding_cache.db                     # 下次摄入重建
docker system prune -a                         # 清理 Docker 缓存（会删除未用镜像）
```

## 8. 运维脚本速查

```bash
# === 常用一键命令 ===

# 健康检查一站式
curl -s http://localhost:8000/health && echo "" && \
curl -s http://localhost:8000/api/v1/admin/stats | python -m json.tool

# 快速查看最近错误
grep -i "error\|exception" logs/app.log | tail -20

# 查看 Milvus 集合信息
curl -s http://localhost:8000/api/v1/admin/stats | \
  python -c "import sys,json; d=json.load(sys.stdin); print(f\"Chunks: {d.get('total_chunks',0)}, Docs: {d.get('total_documents',0)}\")"

# 重启并等待就绪
docker compose -f deploy/docker-compose.yml restart api && \
sleep 10 && \
curl -s http://localhost:8000/health
```
