# 01b — 快速入门与部署指南

> **目标读者**: 运维人员、项目经理、非技术背景的部署操作者。
> **目标**: 30 分钟内完成系统首次部署，并能进行基本验证。

## 1. 前置条件检查

### 1.1 硬件最低要求

| 资源 | 最低配置 | 推荐配置 | 说明 |
|------|----------|----------|------|
| CPU | 4 核 | 8 核+ | Intel/AMD x86_64 或 Apple Silicon (M1+) |
| 内存 | 16 GB | 32 GB+ | 含 Milvus (4GB) + BGE-M3 模型 (2GB) + LLM |
| 磁盘 | 50 GB 可用 | 200 GB+ SSD | 向量库约 2GB + 模型 ~2GB + DOCX 源文件 ~500MB |
| GPU | 无 | NVIDIA 8GB+ / Apple MPS | 加速嵌入生成，非必需 |
| 网络 | 外网（首次） | — | 首次需下载 BGE-M3 模型（约 2.2GB）和 Docker 镜像 |
| 操作系统 | Linux (推荐) | macOS 14+ | Windows 需 WSL2 |

> **磁盘空间估算**: 400 份 DOCX 规范 → 约 3GB 向量数据 + 2GB BM25 索引 + 嵌入缓存。

### 1.2 软件前置条件

| 软件 | 最低版本 | 检查命令 |
|------|----------|----------|
| Python | 3.11+ | `python --version` |
| pip | 24.0+ | `pip --version` |
| Docker | 24.0+ | `docker --version` |
| Docker Compose | v2.0+ | `docker compose version` |
| Git | 2.40+ | `git --version` |
| Node.js (前端) | 18+ | `node --version` |

### 1.3 必须获取的外部资源

| 资源 | 用途 | 如何获取 |
|------|------|----------|
| LLM API Key | 问答生成 | OpenAI / vLLM / 企业内部 API |
| BGE-M3 模型 | 嵌入向量生成 | 首次运行时自动从 HuggingFace 下载 (2.2 GB) |
| 3GPP DOCX 文档 | 知识库源数据 | 从 3GPP FTP 下载 或 已有文档 |

## 2. 三步部署 (Docker 方式，推荐)

> **适用场景**: 生产环境、不想配置 Python 虚拟环境的用户。

### Step 1: 获取代码并配置

```bash
# 1.1 克隆项目
git clone <your-repo-url> 3GPP_RAG_project
cd 3GPP_RAG_project

# 1.2 配置环境变量（只需改一个文件）
cp .env.example .env
```

编辑 `.env` 文件，**只需修改以下 3 行**（其他保持默认即可）：

```bash
# 必填项 — 改成你自己的值
LLM_BASE_URL=https://api.openai.com/v1        # 你的 LLM 服务地址
LLM_API_KEY=sk-your-actual-api-key-here       # 你的 API Key
LLM_MODEL=gpt-4o-mini                          # 模型名称
```

### Step 2: 启动服务

```bash
# 2.1 启动所有服务（首次会自动拉取 Docker 镜像，约 5-10 分钟）
docker compose -f deploy/docker-compose.yml up -d

# 2.2 等待服务就绪（约 30 秒）
sleep 30
```

### Step 3: 验证部署

```bash
# 3.1 检查 Milvus 是否运行
curl http://localhost:9091/healthz
# 应返回: OK

# 3.2 检查 API 是否运行
curl http://localhost:8000/health
# 应返回: {"status":"ok","milvus":true}

# 3.3 检查前端是否运行
curl -o /dev/null -s -w "%{http_code}" http://localhost:3000
# 应返回: 200
```

**部署成功！** 🎉 现在可以进行首次文档摄入了。

## 3. 三步部署 (本地开发方式)

> **适用场景**: 开发调试、不想用 Docker 的用户。

### Step 1: 安装依赖

```bash
cd 3GPP_RAG_project

# 1.1 创建虚拟环境
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate

# 1.2 安装 Python 依赖
pip install -r requirements.txt

# 1.3 安装前端依赖
cd frontend && npm install && cd ..
```

### Step 2: 配置并启动 Milvus

```bash
# 2.1 配置 .env (同 Docker 方式)
cp .env.example .env
# 编辑 .env: 填写 LLM_API_KEY

# 2.2 仅启动 Milvus（用 Docker）
docker compose -f deploy/docker-compose.yml up -d milvus
sleep 30
```

### Step 3: 启动后端和前端

```bash
# 3.1 启动 API 服务（终端 1）
python -m src.main
# API 运行在 http://localhost:8000

# 3.2 启动前端（终端 2）
cd frontend && npm run dev
# 前端运行在 http://localhost:3000
```

## 4. 首次文档摄入

部署完成后，向量库是空的，需要摄入 3GPP 文档。

### 4.1 放置文档

将你的 DOCX 文档按系列号放入对应目录：

```
data/documents/R18/
├── 21_series/    ← 放 21 系列的 DOCX
├── 22_series/    ← 放 22 系列的 DOCX
├── 23_series/    ← 放 23 系列的 DOCX (5G Core)
├── 24_series/    ← 放 24 系列的 DOCX
├── 36_series/    ← 放 36 系列的 DOCX (LTE)
└── 38_series/    ← 放 38 系列的 DOCX (NR Radio)
```

> **命名规则**: 文件名建议保持 3GPP 原始命名，如 `TS_38.413_R18_v17.8.0.docx`。系统会从文件名自动解析规范号和 Release。

### 4.2 执行全量摄入

```bash
# 摄入全部文档（首次约需 30-120 分钟，取决于文档数量）
python scripts/bulk_ingest.py

# 进度示意：
# [1/400] TS 21.101 R18 → 提取 ✓ → 分块 45 → 嵌入 ✓ → 入库 ✓
# [2/400] TS 22.001 R18 → 提取 ✓ → 分块 12 → 嵌入 ✓ → 入库 ✓
# ...
# ✅ 摄入完成! 共 48231 chunks, 嵌入缓存命中 0 条
```

### 4.3 验证摄入结果

```bash
# 方式 1: Admin API 查看统计
curl http://localhost:8000/api/v1/admin/stats | python -m json.tool

# 方式 2: 打开浏览器访问 Admin 面板
# http://localhost:3000/admin → 查看仪表盘统计数据

# 方式 3: 快速测试搜索
curl "http://localhost:8000/api/v1/search?q=PDU+Session+Establishment&top_k=5"
```

## 6. 常见首次部署问题

| 问题 | 症状 | 解决方法 |
|------|------|----------|
| **Milvus 启动失败** | `docker ps` 看不到 milvus | `docker compose -f deploy/docker-compose.yml logs milvus` 查看日志；可能是端口 19530 被占用 |
| **BGE-M3 下载失败** | 摄入报 `HuggingFace Hub HTTPError` | 设置环境变量 `export HF_ENDPOINT=https://hf-mirror.com` 后再运行 |
| **LLM 连接失败** | 问答返回 "LLM 调用失败" | 检查 `.env` 中 `LLM_BASE_URL` 和 `LLM_API_KEY` 是否正确 |
| **前端空白页** | localhost:3000 打不开 | 检查 `frontend/.env.local` 中 `NEXT_PUBLIC_API_URL=http://localhost:8000` |
| **摄入内存不足** | 摄入时进程被 kill | 设置 `EMBEDDING_DEVICE=cpu` 避免 MPS 内存泄漏；或减少文档批次 |
| **端口冲突** | `address already in use` | 修改 `docker-compose.yml` 中的端口映射，或停用占用端口的程序 |
| **无文档可摄入** | 摄入日志显示 0 文件 | 确认 DOCX 文件已放入 `data/documents/R18/` 对应系列目录 |
| **Docker 未运行** | `Cannot connect to Docker daemon` | 启动 Docker Desktop，或 `sudo systemctl start docker` |
