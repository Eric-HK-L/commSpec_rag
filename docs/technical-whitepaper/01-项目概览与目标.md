# 01 — 项目概览与目标

## 1.1 项目背景

3GPP (3rd Generation Partnership Project) 是全球移动通信标准的制定组织，每年发布数百份技术规范 (Technical Specification, TS) 和技术报告 (Technical Report, TR)，涵盖 5G NR、LTE、UMTS 等核心技术领域。这些文档以 DOCX/MS Word 格式发布，动辄数千页，工程师在检索特定技术细节时面临巨大挑战：

- **信息分散**: 一个技术主题（如 PDU Session Establishment）可能跨越 TS 23.501、TS 38.413、TS 38.300 等多份文档
- **版本复杂**: 同一规范在 R15/R16/R17/R18 不同 Release 中存在差异，逐版对照耗时巨大
- **术语晦涩**: 3GPP 规范使用大量缩写和协议术语，传统关键词搜索难以覆盖语义相近的表述
- **离线环境**: 通信行业客户通常部署于内网/隔离环境，无法依赖公有云 LLM 服务

本项目 **3GPP RAG 融合系统** 旨在通过 **检索增强生成 (Retrieval-Augmented Generation, RAG)** 技术，构建一个面向电信领域的智能知识库系统，支持自然语言查询、语义搜索、多语言问答，并提供完整的文档管理、运维监控和评测体系。

## 1.2 项目目标

### 核心目标
1. **智能检索**: 基于 Dense 向量 + BM25 稀疏向量的混合检索，支持跨 Release、跨规范的高精度语义搜索
2. **RAG 问答**: 集成 LLM 的增强式问答，带来源追溯 (Source Attribution) 和幻觉检测
3. **全流程自动化**: DOCX 文档自动提取、分块、嵌入、入库，支持增量和全量摄入
4. **离线可部署**: 完整的本地化部署方案，无需外部网络依赖
5. **可观测性**: Prometheus 指标、结构化日志、Admin 管理控制台

### 质量目标
| 指标 | 目标值 | 当前状态 |
|------|--------|----------|
| Recall@10 | ≥ 0.85 | ✅ 0.89 |
| MRR | ≥ 0.70 | ✅ 0.76 |
| 检索 P50 延迟 | < 200ms | ✅ ~150ms |
| 前端构建 | 0 error | ✅ 12 routes |
| Python 测试 | 100% pass | ✅ 327/327 |

## 1.4 项目演进历程

| Phase | 范围 | 关键交付 |
|-------|------|----------|
| Phase 1 (MVP1) | 基础架构 | Milvus 向量库、混合检索、RAG 问答 |
| Phase 2 | 文档摄入 | DOCX→MD 提取器、分块器、BGE-M3 本地嵌入 |
| Phase 3 (MVP3) | 前端+流式 | Next.js UI、SSE 流式生成、对话历史 |
| Phase 4 | 增强优化 | Admin 控制台、i18n、多跳检索、交叉引用、监控、嵌入缓存 |

## 1.5 使用场景

### 场景 1: 协议工程师查询
> "5G 中 PDU Session 建立的 NAS 层流程是什么？涉及哪些 IE？"
→ 系统检索 TS 23.502 + TS 24.501，生成结构化回答，附带规范引用溯源

### 场景 2: 跨版本对比
> "TS 38.413 在 R17 和 R18 中关于 NGAP 过程有什么变化？"
→ Release 感知检索分别拉取两个版本的 chunks，对比分析

### 场景 3: 多语言支持
> [中文输入] "5G核心网的网络切片选择流程"
→ 检测中文 → 翻译为英文检索 → 英文答案回译为中文
