## 2.3 数据流详解

### 2.3.1 查询流 (RAG Pipeline)

```
用户查询 (任意语言)
  │
  ├─ Step 0: i18n 检测 → 翻译为英文
  │     └─ [LLM] translate_to_english()
  │
  ├─ Step 1: 查询扩展
  │     └─ [LLM] build_query_expansion_prompt() → 扩展关键词
  │
  ├─ Step 2: 生成查询嵌入
  │     └─ [LLM.embed()] → BGE-M3 1024-dim 向量
  │
  ├─ Step 3: 混合检索
  │     ├─ Dense Search (Milvus ANN)
  │     ├─ BM25 Sparse Search
  │     └─ RRF 融合 → Top-K 候选
  │
  ├─ Step 3.2: 多跳检索 (条件触发)
  │     ├─ 检测多样性 < 阈值 → 触发
  │     └─ MultiHopRetriever.search()
  │
  ├─ Step 3.4: 交叉引用解析
  │     ├─ extract_references() → 提取 TS 38.413 §8.3.1
  │     └─ 二次定向检索 → 补充上下文
  │
  ├─ Step 3.5: 检索质量评估
  │     ├─ evaluate_quality() → 密度/多样性/覆盖度
  │     └─ diagnose_quality() → 降级策略建议
  │
  ├─ Step 3.6: Spec-Aware + Cross-Encoder 精排
  │     ├─ Reranker: α×reranker + (1-α)×original 融合
  │     └─ Spec-Aware: 目标规范 boost ×2.0
  │
  ├─ Step 3.7: Release 感知
  │     ├─ detect_release_intent() → R18/R17/Comparative
  │     └─ build_release_context() → 筛选目标 Release chunks
  │
  ├─ Step 3.8: 在线搜索补充 (条件触发)
  │     ├─ should_supplement(score, count)
  │     ├─ TSpec-LLM (官方) → Google CSE (补充)
  │     └─ format_as_context() → 附加到 prompt
  │
  ├─ Step 4: 构建 RAG Prompt
  │     └─ build_rag_prompt(query, chunks, release_note, online_context)
  │
  ├─ Step 5: LLM 生成
  │     └─ LLMClient.chat(messages) → 英文答案
  │
  ├─ Step 5.5: i18n 回译
  │     └─ translate_from_english() → 用户源语言
  │
  └─ Step 6: 答案验证
        └─ AnswerVerifier.verify() → 幻觉检测 + 覆盖度评分
```

### 2.3.2 摄入流 (Ingestion Pipeline)

```
DOCX 文件目录 (data/documents/R18/)
  │
  ├─ Step 1: 下载 (可选, 3GPP FTP)
  │     └─ SpecDownloader.download()
  │
  ├─ Step 2: 查找 DOCX
  │     └─ rglob("*.docx") → 按 Series 排序
  │
  ├─ Step 3: 提取 Markdown
  │     ├─ PandocExtractor.extract_file(docx)
  │     ├─ 解析表格、标题层级、公式
  │     └─ 输出: ExtractionResult(markdown, spec_number, release)
  │
  ├─ Step 4: 分块
  │     ├─ HeaderAwareSplitter.split_document(md)
  │     ├─ 按 ### 标题边界分块 (语义完整性)
  │     ├─ 字节上限 55KB 硬截断
  │     └─ 输出: list[Chunk(text, meta, section_id, title)]
  │
  ├─ Step 5: 嵌入 (含双层缓存)
  │     ├─ EmbeddingCache (SQLite) → 批量命中检查
  │     ├─ File Cache (.npy) → 兜底
  │     ├─ BatchEmbedder (BGE-M3 via SentenceTransformers)
  │     │   或 MPSChunkedEmbedder (Apple Silicon GPU)
  │     └─ 输出: np.ndarray (N, 1024)
  │
  ├─ Step 6: 入库 Milvus
  │     ├─ MilvusStore.insert(chunks) → 微批次 1000 条/批
  │     └─ 自动创建索引 (IVF_FLAT / HNSW)
  │
  └─ Step 7: 重建 BM25 索引
        ├─ 全量: build_bm25(texts, doc_ids, specs, indices)
        └─ 增量: rebuild_bm25_from_collection()
```

## 2.4 并发模型

- **API 层**: FastAPI + Uvicorn (单进程 ASGI)，通过 `asyncio` 处理并发请求
- **LLM 调用**: 同步阻塞（简化实现），通过 `cachetools.TTLCache` 缓存结果减少调用
- **摄入**: 批量处理，支持 MPS 子进程隔离（避免 gRPC 状态污染）
- **监控**: 独立 daemon 线程运行 Release Monitor（每 120 分钟扫描文档变更）

所有配置通过 `src/config/settings.py` 集中管理，基于 `pydantic-settings` 从 `.env` 文件自动加载。参见 [[附录A-配置参考]] 获取完整配置项说明。


## 2.6 硬件需求与资源规划

### 最低配置（开发/评估环境）

| 资源 | 规格 | 说明 |
|------|------|------|
| CPU | 4 核 x86_64 或 Apple M1+ | 含嵌入模型推理 |
| 内存 | 16 GB | Milvus (4GB) + BGE-M3 (2GB) + API (1GB) + 系统 |
| 磁盘 | 50 GB SSD | 向量库 ~3GB + 模型 ~2GB + DOCX ~0.5GB + Docker 镜像 |
| GPU | 无 | BGE-M3 可在 CPU 上运行（较慢） |
| 网络 | 出站 HTTPS | 首次下载模型 (2.2GB) + LLM API 调用 |

### 推荐配置（生产环境）

| 资源 | 规格 | 说明 |
|------|------|------|
| CPU | 8+ 核 | 含精排 Cross-Encoder 推理 |
| 内存 | 32 GB | 为数据增长留余量 |
| 磁盘 | 200 GB+ NVMe SSD | 向量库随文档数量线性增长 |
| GPU | NVIDIA 8GB+ VRAM | 加速 BGE-M3 嵌入 + Cross-Encoder 精排 |
| 网络 | 内网千兆 | API↔Milvus↔LLM 低延迟互联 |

### 存储容量估算

| 数据规模 | 文档数 | Chunk 数 | 向量库大小 | BM25 索引 | 嵌入缓存 |
|----------|--------|----------|-----------|-----------|----------|
| 小（1 个系列） | ~50 | ~8K | ~500 MB | ~200 MB | ~100 MB |
| 中（R18 全量） | ~400 | ~50K | ~3 GB | ~2 GB | ~200 MB |
| 大（多 Release） | ~1000 | ~150K | ~10 GB | ~5 GB | ~500 MB |

> 磁盘总需求 ≈ 向量库 × 2.5（含索引、BM25、缓存、日志）

## 2.8 错误处理与传播路径

### 错误传播链

```
用户请求 → API 层 → Pipeline → 各子模块
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
      检索失败      LLM 调用失败    验证失败
          │             │             │
          ▼             ▼             ▼
    [降级策略]    [降级策略]    [降级策略]
    返回空结果     返回错误提示   标记未验证
          │             │             │
          └─────────────┼─────────────┘
                        ▼
              APIResponse {
                success: false/true,
                data: {...},
                error: "...",      ← 用户可读错误
                warnings: [...]     ← 非致命警告
              }
```

### 各层错误处理策略

| 层级 | 错误类型 | 处理策略 | 用户影响 |
|------|----------|----------|----------|
| API 层 | 参数校验失败 | 返回 400 + 错误描述 | 直接提示 |
| API 层 | 认证失败 | 返回 401 | 直接提示 |
| Pipeline | 查询扩展失败 | 使用原始查询 | 无感知 |
| Pipeline | 嵌入生成失败 | 零向量兜底 | 检索质量可能下降 |
| Pipeline | 混合检索异常 | HTTPException 500 | 错误提示 "检索服务暂时不可用" |
| Pipeline | 多跳检索失败 | 使用单跳结果 | 无感知 |
| Pipeline | Cross-Encoder 失败 | 使用原始 RRF 排序 | 精排效果缺失 |
| Pipeline | LLM 调用超时 | 重试 1 次 → 返回错误 | "LLM 服务响应超时，请稍后重试" |
| Pipeline | 在线搜索失败 | 仅返回离线结果 | 在线补充缺失 |
| Pipeline | 答案验证失败 | 标记 `verified=false` | 答案附带警告 |
| Pipeline | i18n 翻译失败 | 返回英文原文 | 语言不符合预期 |
| 摄入 | 单文件提取失败 | 跳过该文件继续 | 该文档缺失 |
| 摄入 | 嵌入子进程超时 | 降级到 CPU 模式 | 摄入变慢 |
| 摄入 | Milvus 插入失败 | 重试 3 次 → 终止该段 | 部分数据缺失 |
